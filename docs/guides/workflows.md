---
title: Workflow DSL
description: Compose reusable qualitative pipelines with the Pulse workflow builder.
---

The `Workflow` class lets you stitch together data sources and Pulse processes using a fluent API.
It tracks dataset aliases, infers dependencies, and keeps outputs addressable across the pipeline.

## Anatomy of a workflow

```ts
import { Workflow, CoreClient } from '@rwai/pulse'

const wf = new Workflow()
    .source('comments', ['Love the design', 'Navigation is clunky'])
    .sentiment({ name: 'commentSentiment' })
    .themeGeneration({ maxThemes: 6 })
    .themeAllocation({ themesFrom: 'themeGeneration_1', name: 'commentThemes' })
    .cluster({ source: 'comments', name: 'commentClusters' })

const client = new CoreClient({ auth })
const results = await wf.run({ client })
```

Every process automatically stores its output using the process id (or the custom `name` you pass).
Later steps can read from that alias via options such as `source`, `inputs`, or `dependsOn`.

## Sources and inputs

- Use `.source(alias, data)` to register in-memory arrays, CSV rows, or any structure supported by downstream processes.
- Provide `datasets` to `workflow.run({ datasets })` when you want dynamic payloads at runtime.
- Pulse defaults to a `dataset` alias. If you never call `.source`, the Analyzer path is used instead (see below).

```ts
wf.source('dataset', ['foo', 'bar']) // overrides the default alias intentionally
```

## Process catalog

Each step mirrors a typed process class in `src/processes/*`. Notable builders include:

| Method | Description | Key options |
| --- | --- | --- |
| `.sentiment()` | Runs VADER-style sentiment with optional fast mode. | `fast`, `source`, `name` |
| `.themeGeneration()` | Derives latent topics. Seeds `themeAllocation` automatically if none exists. | `minThemes`, `maxThemes`, `context`, `fast`, `name` |
| `.themeAllocation()` | Applies custom or generated themes to a dataset. | `themes`, `themesFrom`, `inputs`, `singleLabel`, `threshold` |
| `.themeExtraction()` | Pulls archetypal responses for each theme alias. | `themes`, `themesFrom`, `inputs`, `version` |
| `.cluster()` | Builds semantic clusters via embeddings. | `fast`, `source`, `name` |
| `.createEmbeddings()` / `.compareSimilarity()` | Direct access to vector primitives. | `source`, `name` |
| `.generateSummary({ question })` | Produces tuned summaries or one-pagers. | `question`, `length`, `preset` |
| `.generateDataDictionary()` | Builds DDI Codebooks from 2D tabular arrays. | `inputDataset`, `title`, `language` |

All methods validate that referenced sources exist and will throw early with descriptive errors
(e.g., “Unknown source for cluster: 'foo'”).

## Monitoring hooks

Attach lifecycle callbacks to stream progress into your own logger or telemetry stack:

```ts
wf.monitor({
    onRunStart: () => console.info('workflow starting'),
    onProcessStart: id => console.time(id),
    onProcessEnd: (id, res) => {
        console.timeEnd(id)
        console.debug(`${id} emitted`, Object.keys(res ?? {}).length)
    },
    onRunEnd: () => console.info('workflow finished'),
})
```

## File-based pipelines

Use `Workflow.fromFile` to load JSON definitions generated by low-code builders or spreadsheets.
Each entry must contain exactly one key matching a workflow method.

```json
{
    "pipeline": [
        { "themeGeneration": { "maxThemes": 8 } },
        { "themeAllocation": { "name": "allocation" } },
        { "generateSummary": { "question": "What matters most?" } }
    ]
}
```

```ts
const wf = Workflow.fromFile('./pipelines/pulse.json')
const results = await wf.run({ client, datasets: { dataset: comments } })
```

## Analyzer fallbacks

If you never register sources inside the builder, `.run()` switches to Analyzer mode. This is handy when the process list is static but the datasets arrive per invocation. See the [Analyzer guide](/guides/analyzer) for details.

## Error handling tips

- Prefer unique `name` values so you can destructure `const { insights } = await wf.run(...)`.
- Use `themesFrom` when allocating to previously generated themes; otherwise, the DSL auto-inserts a new themeGeneration step.
- When mixing synchronous (`fast`) and asynchronous processes, monitor for job ids: any helper returning a `JobInfo` can be awaited later via `CoreClient` job APIs.
